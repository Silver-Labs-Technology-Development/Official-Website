BTCS L2

EVM-compatible execution anchored to Bitcoin Silver research.

Current development statusEngineering prototype — not productionSource-based overview · October 2026

BTCS L2 is an experimental second-layer execution platform exploring smart contracts, tokens, BTCS as native gas and a verifiable relationship to Bitcoin Silver L1. It is designed as a real node and network project, not just a wallet page or an EVM demonstration.

View development source ↗Contribute or collaborate
01 / ENGINEERING

What has already been built

  • A local EVM execution engine with JSON-RPC and transition tests is implemented.
  • BTCS L1 anchoring, deposit recovery and withdrawal-state engineering have been exercised in isolated tests.
  • Experimental peer communication exists; production consensus and permissionless operation have not been established.
02 / PRODUCT

What the product is intended to provide

  • EVM-compatible developer tools and permissionless smart contracts once network rules are finalized.
  • BTCS-denominated gas and future cross-layer deposits/withdrawals with verifiable security.
  • Canonical block sync, fork choice, independent validators and economic/settlement finality.

These are separate current and future capabilities, not a claim that every function is already operational.

03 / GET STARTED

How to use or preview

Engineers can run tests and local dev-node profiles from the branch documentation. There is no released public BTCS L2 mainnet or secure production bridge.

04 / PARTICIPATE

How to get involved

Blockchain consensus engineers, formal verification researchers, ZK specialists, P2P developers and security reviewers are invited to review reproducible tests and trust boundaries.

Start from the repository's issues, documentation, test instructions or contribution process. Do not share private keys or production credentials.

05 / RELEASE READINESS

When will it be live?

No mainnet date announced. A verifiable multi-node development network is the next broad milestone.

Before a public readiness claim, these milestones require evidence:

  • Demonstrate multi-node fork choice, block synchronization and finality behavior.
  • Complete independent end-to-end L1 deposit, execution, settlement and withdrawal verification.
  • Finalize production chain ID, network parameters, adversarial tests and threat model.

Launch dates are not estimates unless published separately by the project. Repository activity and passing local tests do not establish safe public operation.

06 / ECOSYSTEM

Silver Labs integrations

SilverPay accounts, SilverForge assets, Silver Scan chain indexing and future SilvEx markets.

Each integration needs separate compatibility, data-quality and security verification. A project being listed or featured does not mean wallets, pools or markets are live.
