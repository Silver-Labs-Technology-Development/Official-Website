Get your environment ready

Open the relevant source repository, read its README and launch or implementation-status files, then reproduce the documented tests. Make a small isolated branch and share a specific issue or proposal instead of changing multiple applications at once. Look for testing requirements that depend on a running node.

03 / 4

Security and responsible development

Never share wallet seeds, private signing keys, RPC credentials or customer data. Use valueless testnet/regtest assets, isolated nodes and mocks. Report vulnerabilities privately through each project's documented security process; no change is production-approved merely because CI succeeds.
